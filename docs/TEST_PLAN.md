# Проверка проекта

Этот документ описывает воспроизводимые сценарии и ожидаемое поведение. Он не утверждает, что каждый пункт уже проверен. Фактический результат запуска нужно фиксировать в выводе команд и итоговом отчёте.

## Автоматические проверки

```bash
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Минимальное покрытие логики: начисление и нижняя граница награды; максимум двух подсказок; ограничение штрафа за ошибки; отсутствие двойных наград; проверка решения; открытие следующей главы; запись/чтение и восстановление повреждённого сохранения; границы трёх финалов.

Проверки браузера должны охватывать прохождение от старта до финала, независимость демо, словарь и небольшие экраны. Если Chromium отсутствует либо автоматизация недоступна, это нужно явно указать в отчёте, сохранив выполненные проверки типов и логики.

## Старт и навигация

| Действие | Ожидаемый результат |
| --- | --- |
| Открыть главную с чистым сохранением | Понятны цель и действие начала; нет ошибки консоли |
| Начать игру | Брифинг читается и пропускается |
| Принять дело | Первая глава доступна, следующие объясняют условие открытия |
| Вернуться на главную и продолжить | Существующее прохождение доступно |
| Перейти в архив, исследование, жюри, тренажёр | Разделы работают вне кампании |
| Открыть неизвестный маршрут | Понятный выход к рабочей странице |

## Кампания

Пройти все пятнадцать заданий. Для каждого убедиться, что обязательные улики заметны и доступны, верное решение можно обосновать данными сцены, ошибку можно исправить, подсказки не завершают задачу автоматически, объяснение связано с контекстом, а слова доступны в архиве.

Особенно проверить:

- задание 1 требует изучить контекст до вывода;
- «тильт» не переводится как физический наклон;
- объяснение «рофла» не оправдывает любое оскорбление;
- пары «вайб»/«кринж» выбираются без перетаскивания;
- конструктор «фиксануть» объясняет русскую адаптацию английской основы;
- последовательность Git различает коммит и отправку;
- «костыль» передаёт временный, а не окончательный характер решения;
- «дедлайн» отличается от начала мероприятия;
- «релиз» отличается от сохранения и запуска программы;
- финальный отчёт включает подтверждённые факты, исключает ошибочные буквальные трактовки;
- после 5, 10 и 15 заданий восстанавливаются соответствующие модули;
- финал достижим даже после ошибок и подсказок.

## Баллы и повторный просмотр

Начальная награда — 100. Первая ошибка снижает её на 15, вторая ещё на 10; последующие не увеличивают штраф. Каждая из двух доступных подсказок снижает награду на 20, но награда не падает ниже 40. Повторное решение, возврат назад и обновление страницы не начисляют её второй раз.

Проверить границы 899/900 и 1249/1250, а также максимум 1500. Все три финала должны давать полноценное завершение.

## Сохранение

1. Открыть улику, выбрать часть ответа, вернуться на карту и продолжить.
2. Обновить страницу на незавершённом задании; доступные сохранённые находки не теряются.
3. Обновить страницу после решения; решение и очки сохраняются вместе.
4. Изменить настройки и обновить страницу.
5. Запросить сброс и отменить; прогресс остаётся.
6. Подтвердить сброс; удаляются только данные игры.
7. Подставить повреждённый JSON или неизвестную версию `slangos_save_v1`; приложение остаётся работоспособным.
8. Проверить понятное поведение, если браузер запрещает запись в `localStorage`.

## Словарь и исследование

- Не менее двадцати полных словарных записей; для каждой есть RU/EN дефиниции, пример, нейтральная формулировка, грамматика, контекст и оговорки.
- Поиск по русскому слову, английскому источнику и части определения; очистка поиска и пустой результат.
- Каждый фильтр показывает соответствующие записи.
- Открытие и закрытие карточки, переходы по связанным словам, доступность источников.
- Гипотезы не выданы за подтверждённые факты; профессиональная лексика не названа целиком общемолодёжной.
- В исследовании есть введение, цель, задачи, методика, классификация, анализ, выводы, источники и полная двуязычная таблица в конце работы.
- Печатный preview использует белый фон и читаемый текст, скрывает игровую навигацию, не обрезает строки таблицы. Проверить все страницы PDF.
- Отсутствуют вымышленные опросы и неподтверждённые проценты эффективности.

## Демо и тренажёр

Сохранить копию сюжетного `localStorage`, пройти демонстрацию жюри и экспресс-тренажёр; сравнить основную кампанию. В демо работают три различных типа задачи; тренажёр выдаёт пять подготовленных вопросов, результат и доступ к словам для повторения.

## Экран и доступность

Проверить ширины 320, 375, 768, 1024 и 1440 px. Не должно быть горизонтального скролла, наложений, обрезанных реплик и недоступных кнопок. Модальные окна должны помещаться или прокручиваться.

Пройти ключевые действия только клавиатурой: Tab/Shift+Tab, Enter/Space, Escape. Проверить видимый фокус, ограничение фокуса внутри модального окна и возврат к открывшей его кнопке. Убедиться, что важные сообщения доступны assistive technology, состояние передаётся текстом, а уменьшение анимаций учитывает системную настройку.

## Production

Запустить `npm run preview` после сборки. Проверить базовый путь `/slang-os/`, загрузку ресурсов, обновление внутри разделов, отсутствие критических ошибок консоли и отсутствие обязательных внешних API. Успешная локальная сборка не подтверждает фактическую публикацию на GitHub Pages.
